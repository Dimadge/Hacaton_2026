# Проверки, тест-кейсы и зафиксированные результаты

## Результаты, фактически подтверждённые в ходе подготовки

| Проверка | Наблюдение | Статус |
| --- | --- | --- |
| Docker `db` и `api` | `healthy` на НГТУ | Подтверждено |
| `GET /health` | HTTP `200 OK` | Подтверждено |
| API за Nginx: `GET /api/v1/products` | HTTP `200 OK`, продукты `INVESTMENT` и `WORKING_CAPITAL` | Подтверждено |
| Unit/API-тесты в контейнере с локальным флагом демо-OTP | `105 passed, 1 warning` | Подтверждено |
| Регистрация нового клиента с ИНН из demo-реестра | FNS=`active`, BKI=`good` в PostgreSQL | Подтверждено |
| Банковский `PATCH` оценки залога | HTTP `200`, статус залога `ACCEPTED` | Подтверждено |
| Учёт залога и DS в кабинете банкира | На тестовой заявке отображены DS=13 000 ₽/мес. и лимит залога=1 400 000 ₽ | Подтверждено для сценария |
| Полный `DRAFT → DISBURSED` в браузере на НГТУ | Отдельная проверка не предоставлена | **Не подтверждено** |
| Публичный сайт с телефона | Отдельная проверка не предоставлена | **Не подтверждено** |

В публичной конфигурации `DEMO_SIGNING_CODE_VISIBLE=false` пять тестов подписи ожидаемо упирались в `503 DEMO_CODE_DISABLED`; повторный запуск `docker compose exec -e DEMO_SIGNING_CODE_VISIBLE=true api python -m pytest -q` дал **105 успешных тестов**. Это тестовый режим только внутри процесса `pytest`, а не изменение публичного API.

## Приёмочные сценарии

| ID | Роль | Проверка | Ожидаемый результат |
| --- | --- | --- | --- |
| T01 | Гость | Открыть сайт / список продуктов | Список двух кредитных продуктов |
| T02 | Гость | Зарегистрировать новый тестовый ИНН, существующий в демо-реестре | Компания, пользователь и mock-профиль созданы |
| T03 | Клиент | Новая заявка, валидация суммы/срока и финансов | `DRAFT`, запись в PostgreSQL |
| T04 | Клиент | Отправка заявки | `CHECKING`, FNS/BKI сохранены |
| T05 | Банкир | Рассчитать скоринг / проверить заявку | Риск и одно из допустимых решений |
| T06 | Банкир | Оценить залог, отсутствие обременений | `ACCEPTED`, `assessed_value`, `reviewed_by/at` |
| T07 | Банкир | Попробовать 1,5 млн при оценке 2 млн и LTV 70% | Превышение залогового лимита отклонено |
| T08 | Банкир | Одобрить сумму в пределах залога, но выше DS | Одобрение блокируется из-за нагрузки |
| T09 | Клиент + банк | Запросить дополнительные сведения | `NEED_INFO → CHECKING` после повторной подачи |
| T10 | Банк | Критическая БКИ | `REJECTED`, код причины сохранён |
| T11 | Клиент | Выбрать предложение | `OFFERED → ACCEPTED` |
| T12 | Клиент | Демо-OTP и симулированная выдача (локально) | `SIGNED → DISBURSED` |
| T13 | Клиент | Чужой UUID заявки | `404` или запрещённый доступ |
| T14 | Клиент | Эндпоинт банкира с клиентским JWT | `403 FORBIDDEN` |
| T15 | Клиент | Повторный POST с прежней `version` | Конфликт версии |
| T16 | Любая роль | Некорректный OTP / истечение срока / попытки | Подписание запрещено |
| T17 | Оператор | Чистый запуск через Compose + seed | Сервисы запускаются и демо-аккаунты доступны |

Строки T01–T17 — **план приёмки**, не утверждение, что все шаги уже выполнялись вручную. Полная инструкция исполнения: [DEMO_GUIDE.md](DEMO_GUIDE.md).

## Запуск автоматических тестов

```bash
docker compose exec -e DEMO_SIGNING_CODE_VISIBLE=true api python -m pytest -q
```

Для сценариев с настоящей БД используются отдельные HTTP/SQL-проверки; 105 тестов не доказывают производственную готовность, безопасность или гарантированную работу браузера на всех устройствах.
